# 版本记录

以下为当前修改版的主要变化，本地构建产物位于 `dist/`。构建所用的原始 Windows EXE 与 Android APK 来自 [Abyxs/codex-mobile-assistant 的 Releases](https://github.com/Abyxs/codex-mobile-assistant/releases)。

## 2.1.1 · Windows / Android

**并发与数据安全**

- **队列连接**：`TaskQueue` 改用单一 `check_same_thread=False` 连接并让所有读-改-提交都落在同一把锁内，跨线程提交不再相互截断。新增 `dispatch_lock` 串行化「选定队首→标记发送→派发」整段，`sendnow` 与后台轮询不再可能同时发出两条消息。
- **队列顺序**：此前按 `created, id` 排序，同一毫秒入队的消息会退化成按随机 UUID 排序，队首可能在两次读取之间变化。改为按 `rowid`（插入序）。
- **队列关闭**：`close()` 现在幂等、不抛异常，总是关闭连接并清理 WAL 残留文件，worker 未及时退出也不会留下文件句柄。
- **队列静默失败**：`_dispatch`、`tick` 与 `sendnow` 的裸 `except` 补上日志，此前桥接故障会静默停止整条队列且无任何线索。
- **详情缓存**：`forget_detail()` 现在同时清空详情、上下文与状态缓存，并移除消息／回复版本记录；`git`、`queue`、`upload` 三条提前返回的写路径也会失效缓存，不再返回过期内容。
- **状态缓存**：`task_status()` 拆出无锁实现，仅当新快照更新时才回写，避免旧结果覆盖新结果。

**安全**

- **路径校验**：`native_features.file()` 改用新增的 `absolute_inside()`，拒绝空字节与 UNC／扩展长度前缀，并要求解析后的路径确实位于允许根目录下且是文件。此前直接 `Path(requested).resolve()` 可绕过 `contained()` 检查。
- **隧道二进制**：启动 `cloudflared` 前校验其 SHA-256 与 `assets/bin/cloudflared.sha256` 一致，不匹配即拒绝执行；构建脚本会记录该摘要。
- **电脑身份**：Android 端此前只在 POST 时比对 `computerId`，所有轮询 GET 都接受任何持有有效令牌的主机。现在读取与写入都校验。

**界面**

- **分隔线**：1px 分隔线改用按画布亮度自适应的 `NativeUi.rule()`，对比度从 1.14–1.80 提升到 3.32–3.86。
- **主按钮文字**：新增 `onPrimary()`，暗色主题下主按钮文字由 1.84 提升到 9.07，各主题均达 5.3 以上。
- **次色文字**：`MUTED` 由 `#727b73` 改为 `#5b625d`，浅色系全部达到 6.08 以上，不再低于 4.5。
- **滚动条**：闲置滚动条改为按画布混合的 `scrollbar()`，浅色主题下由 1.66–1.80 提升到 7.33 以上。
- **列表回收**：`MessageAdapter` 新增三种视图类型，修复 Button 与 LinearLayout 共用回收池导致的错乱。
- **消息正文**：7 处 `Pattern.compile` 提为静态常量，滚动时不再反复编译正则。
- **点击区域**：队列操作按钮、附件「移除」、悬浮导航按钮全部提升到 48dp。
- **触摸反馈**：统一用主题主色派生涟漪与滚动条颜色，暗色主题下不再出现突兀的深绿。
- **弹窗**：遮罩浓度按主题亮度调整，暗色主题下不再过浅。
- **键盘与输入**：API 30 以下用 `getWindowVisibleDisplayFrame` 检测键盘，输入框最少行数随之调整。
- **设置页**：滑动收起顶栏、任务通知、实时悬浮窗三项从游离状态归入「通知与悬浮窗」分组。
- **空项目名**：会话目录解析为空时显示「未指定项目」而不是空白。
- **上传提示**：会话切换或图片读取失败时给出明确提示，不再静默无反应。
- **生命周期**：多处 `postDelayed` 补上 `isDestroyed()` 守卫；`onDestroy` 关闭目录浏览器与提问弹窗，不再泄漏 Activity。
- **图标回退**：通知与导航图标在资源缺失时回退到系统图标，不再显示空白。

**表面层级与主题配色**

界面看着"没有对比度"，根因不是主题选得不好，而是七个主题的三种表面色被压在同一个近白点上，色相也只是同一格色的微弱偏移。用实测数据说明：

- **表面挤在一起**：修前画布 `.982`、输入框底 `.950`、卡片 `.910`，饱和度系数只有 `.14/.22/.38`。亮色主题下输入框底与画布只有 **1.07:1**，肉眼无法分辨，这就是"输入框背景几乎完全透明"。
- **主题彼此相同**：五个亮色主题的画布实测为 `#fafbfa / #fafbfa / #fafafb / #fafafa / #fbfafa` —— 差异只有一两个色阶。其中 `light` 与 `green` 的对比度是 **1.0000**，数学上完全相同。这就是"主题是没有对比度的纯色"。
- **改法**：新增 `LIGHT_SURFACES` 逐主题写出画布、卡片、输入框、选中态、分隔线五档饱和度与亮度，不再由一个色度系数派生——那正是七个主题塌成同一个颜色的原因。每个主题现在带自己的色相，画布实测为 `light #f8f9f9` 中性、`green #e6f5ed` 带绿、`ocean #e7eff5` 偏冷、`lavender #efe9f4` 带紫、`sand #f5ede3` 偏暖、`midnight #121419`。
- **输入框可辨**：填充与画布提到 **1.16–1.22:1**，边框仍解到 3:1。此前边框虽然解到了 3:1，但填充几乎与背景同色，整体仍像透明的框。
- **连带的文字对比**：`SOFT` 调暗后，`MUTED` 在输入框底上掉到 4.08，因为它是解到卡片色而非实际承载它的表面。改为解到卡片与输入框底中更难的那个（暗色主题取相反的一侧），七主题全部回到 4.5 以上。
- **新增圆角**：`CORNER_DISC 23`——悬浮导航按钮 46dp 的半径，等于边长一半才是正圆，用其余四档只会得到圆角方块。

**悬浮窗与折叠区域**

- **悬浮窗依旧不显示（本轮定位到真因）**：`render()` 原本只由「收到电脑状态」和「连接中断」两条路径触发，而 `TaskNotificationService.checkOnce()` 在**尚未配对、没有 token 时直接 `return`**，根本没走到 `overlay.update()`。于是开关打开、权限也给了的设备上，宠物在等一条永远不会来的消息——上一轮只加了诊断，没有触达这一层。现在：无 token 时也投递一个空状态让宠物先出现（它是状态显示器，不是状态本身）；开关打开时立即 `prime()` 一次；设置页的检查框增加「立即显示悬浮窗」按钮。同时修掉一个必然踩中的矛盾——检查框是在 App 前台按下的，而前台门闸恰好会拒绝这次绘制，所以 `forced` 让手动触发可以穿过门闸。
- **折叠条没有文字**：图标用 `leading()` 放在文字**前面**，而 `Button` 自带最小宽度与图标间距，布局时先满足图标再量文字，文字被压到零宽——整行只剩一个箭头。新增 `trailing()` 把图标放到文字之后。同一问题在会话折叠条和任务面板两处。
- **任务面板折叠条**：原来先建空标签按钮、两行后再 `setText`，空标签会先参与测量；现在标签在构造时就位。
- **回到顶部/底部失效（真因在 `INVISIBLE`）**：`updateNavigation()` 用 `setVisibility(INVISIBLE)` 表示「这个方向没得跳」，而 `INVISIBLE` 的子视图**会被父视图的命中测试跳过**。短对话同时处于顶部和底部，于是两枚都被标成不可见——手柄还在，底下却没有任何可点的子视图，点哪都没反应。淡出到 alpha 0 也帮了倒忙：一个全透明的手柄在观感上就是不存在。现在不可用的一侧**只降透明度到 0.3**、保持 `VISIBLE`，命中测试照常，内容描述改成「已经在顶部／已经在最新位置」；淡出也只到 0.12 而不是 0。两条跳转本身也复核过：`jumpToTop()` 原本在无更早历史时调 `positionBoundary(false)`，语义是「贴到底部」，与按钮名字相反，改为 `setSelection(0)`。
- **回到顶部/底部仍然失效（第二次定位，真因在 `setPressed`）**：修完 `INVISIBLE` 后用户反馈依旧。用真实触摸注入逐层排查：焦点、坐标、命中测试全部正确（手工命中测试返回 `top` 按钮本身），但 `performClick()` 有效而真实触摸无效，`navigationVersion` 纹丝不动。差在事件序列——`FloatingNavigation` 的拖拽监听在 `ACTION_UP` 里先调了 `v.setPressed(false)`，而 `OnTouchListener` **先于** `Button.onTouchEvent` 执行；后者只在 `isPressed()` 为真时才 `performClick()`，于是每一次点击都在判定那一刻被自己解除，永远不触发。拖动时仍需消费事件，因此只在未拖动分支不再清 pressed 状态，把手势交回 `Button` 自己收尾。实测点击后 `navVersion` 2→3、列表首项 19→0。
- **按钮显示不完整**：容器在调用处写死 `50×102`，而两枚 46dp 圆盘加 8dp 间距需要 100dp，于是两枚都被裁掉一截。现在尺寸由 `FloatingNavigation` 自己的常量推导，调用处引用它们而不是复述数字。
- **按钮不是圆形**：用的是 24 圆角配 48dp，一旦尺寸被压缩就不再是圆；现在半径取圆盘边长一半，并清掉 `iconButton` 自带的 12dp 内边距，让圆填满整个方块。
- **设置项展开样式重写**：展开区原本直接铺在卡片上，左缩进 50dp 而右缩进 10dp。现在标题行是填充色的一行、展开区是卡片内的独立浅色区块并在四边内缩，标题在展开时着色并同时显示当前值，当前值从右侧移到标题下方，不再与箭头争同一个位置。
- **一次点击不够高**：折叠条按需求压到一行文字高（约 30dp），低于 48dp 的最小触摸目标。用 `TouchDelegate` 向上下各扩出一段命中区，视觉高度不变而触摸区域达标——**注意委托必须挂在父容器上、目标为子视图**，这一处与统计条那处起初都写成了指向自己，造成了栈溢出，详见下方「闪退」。

**主题名称与选中项错位**

- **选「墨绿」得到一片灰黑、选「新叶」得到浅绿**：`THEMES` 是 `light/green/ocean/lavender/sand/dark/midnight`，而 `THEME_NAMES` 当时从第二项起整体错位一格——「墨绿」落在 `dark`、「远洋」落在 `lavender`。选中项因此与实物不符。顺带发现 `LIGHT_SURFACES` 的行序本来就是对齐的，所以 `ladder()` 的 `indexOf` 一直是好的，坏的只有供显示的名字表。两份列表现在逐项对齐。
- **主题之间看不出差别**：即便选对，六个浅色主题的画布饱和度也只在 `.24–.38`、明度 `.955–.975`，渲染出来是同一种米白。本轮把各主题的画布、卡片、输入框、选中态、分隔线五档一并加深并给出各自的色相偏向（新叶偏绿、远洋偏冷、紫藤偏紫、暖沙偏暖）。这是上一轮「表面层级」工作的继续：那时先把三档表面从同一个近白点拉开，这一轮把七个主题从彼此之间拉开。

**输入区上方的统计条**

- **统计条比一行文字高得多**：`renderTasks()` 里 `add(taskPanel, barHolder, barH)` 把**已经是像素**的 `barH` 又过了一遍 `dp()`。`taskBarHeight()` 返回的是量出来的像素值（已夹在 32dp–48dp），在 420dpi 屏上被再乘 2.625 倍，于是 96px 变成 288px。改为直接 `taskPanel.addView(barHolder, new LinearLayout.LayoutParams(-1, barH))`。同一处折叠详情的高度上限也一并收敛，内容为空时为 0。实测 `barHolder h=96 lp=96`，正好一行。
- **输入框底部的折叠图标看不见**：该控件一直存在且工作正常——实测 120×120px、内容描述「收起输入选项」，真实触摸两次分别在 `GONE`／`VISIBLE` 间切换模型、思考、审批、插件这一排 chip。看不见的原因是底色用了 `SOFT`，而它所在画布与 `SOFT` 只差一档，整行看上去在右端空了一截。底色改为 `TINT`，图标尺寸由 22 提到 26，让它在同排控件里明确读作一个按钮。

**悬浮窗气泡**

- **展开后关不掉**：窗口带 `FLAG_NOT_TOUCH_MODAL`，气泡之外的触摸会直接穿过应用到下层。新增一层全屏透明的触摸捕获窗口，只在气泡打开期间存在，收到任意 `ACTION_DOWN` 即关闭气泡。由于悬浮窗按添加顺序叠放，捕获层加入后需把宠物窗口重新添加一次，否则会被压在下面连拖动一起失效；重加失败时回滚，不留半个捕获层。
- **气泡引出箭头悬空**：`SpeechBubble` 的箭头恒定画在气泡**底边**，而气泡与宠物是左右并排的，箭头指着空气。改为从**朝向宠物的那一侧**伸出，垂直落在气泡高度的 62% 处；左右方向由宠物当前在屏幕哪半边决定。内边距同步从「底部留箭头」改为「对应侧留箭头」。
- **字号偏大**：标题由 `LABEL`(13sp) 降为 `CAPTION`(11sp)，正文由 `BODY`(15sp) 降为 `LABEL`(13sp)。
- **气泡里出现「正在执行：执行结果」这类非中文结构的碎句**：`prose()` 此前只用「这一行有没有汉字」过滤，而这类状态标签通篇是汉字，于是一条不落地全放了出来。新增 `isStatusLabel()`：把整行按冒号、逗号、顿号、分隔符拆成片段，**每个片段都是阶段词**（正在执行／执行结果／执行中／正在思考／工具调用／任务状态等）才判定为状态标签并丢弃。关键是它只丢纯标签——`已完成的 3 项步骤已写入 MainActivity.java`、`执行结果：修复了回到顶部的判定`、`正在执行：把页面渲染出来` 都带真实内容，全部保留，不会误杀。

**闪退**

三处点击闪退，前两处是同一个形状：**视图被交给了指向它自己的 `TouchDelegate`**。

- **点击统计条／展开步骤条闪退（真因在自引用委托）**：`View.onTouchEvent` 收到触摸后把事件交给 `TouchDelegate`，而 `TouchDelegate` 又派发回同一个 View，于是 `onTouchEvent → TouchDelegate.onTouchEvent → dispatchTouchEvent → onTouchEvent` 无限递归，栈溢出杀死进程。真机栈为 `java.lang.StackOverflowError`，帧序列在 `TouchDelegate.onTouchEvent(TouchDelegate.java:151)` 与 `View.dispatchTouchEvent` 之间循环。委托的本意是让一行文字高的控件达到 48dp 触摸高度，正确做法是**委托挂在父容器上、目标为子视图**：统计条改为 `barHolder.setTouchDelegate(new TouchDelegate(hit, bar))`，步骤条改为 `head.setTouchDelegate(new TouchDelegate(hit, toggle))`。

  这处缺陷此前多轮排查都没抓到，原因是测试用 `performClick()` 触发。它直接调用监听器、**从不进入 `View.dispatchTouchEvent`**，对委托损坏完全免疫；只有真实手指才会走这条路。现已新增覆盖真实派发路径的断言：`WorkflowRegression.tapView()` 用 `sendPointerSync` 注入指针事件点击统计条与执行组折叠按钮，并在每次点击后断言进程存活。把缺陷临时注入后该断言立即失败，确认它真的守得住。

- **点击「立即显示悬浮窗」闪退**：`render()` 在**主线程**上跑，且是全应用唯一一个用户可以手动触发的绘制入口，所以它抛出的任何异常都会终止进程——用户看到的就是「按这个按钮就闪退」。这正是它此前「依旧不显示」的另一面：不是没画，是画的时候崩了。现在 `render()` 整体包在 `try/catch(Throwable)` 里，失败写入 `blockReason` 并在检查框里显示，`prime()` 在主线程投递体内也再包一层。
- **点击详情面板往上的高度**：详情面板的高度原本**下限固定 64dp**，即使一组里既没有步骤也没有文件，也照样占 64dp。现在高度完全由内容算出，内容为空时为 0。
- 新增 `tools/ui-checks/view_teardown_race.py`：一条检查扫描「监听器内联调用了一个会清空可点击容器的方法」，只对真正包含被点视图的那几个容器（`taskPanel`／`inlineOptions`／`optionsDismiss`）报警，避免 `renderQueue()` 清空 `queuePanel` 这类无关情形淹没结论；另一条检查扫描**自引用委托**（`X.setTouchDelegate(new TouchDelegate(..., X))`），直接读出委托目标与持有者比对，命中即报出行号。

**输入区与会话列表**

- **模型／审批／插件只剩箭头、且只剩「加号和思考」**：两个独立原因。其一，四个选项按 2:1:1:1 分权重挤在一行，每个拿到约五分之一屏宽，扣掉图标与内边距后文字被量成零宽。其二——也是「只剩两个」的直接原因——这一行被放进了 `NativeUi.DockScroll`，而 `DockScroll` 是**垂直** `ScrollView`，把一个横向行塞进去，行会被视口按高度裁掉，只剩最前面一两个可见。现在改用真正的 `HorizontalScrollView`，并去掉 chip 上的箭头（四枚各 24dp、共 96dp，比整段余量还多，而 chip 自身的底色已经表明它可以点）。
- **四个 chip 到底放不放得下**：用实测数字定，不是估。最窄 320dp 屏减去输入区内边距 24dp、加号 40dp 及其间距 8dp，留给 chip 的是 248dp；三枚两字 chip 各约 40dp，间距 18dp，模型 chip 上限 82dp，合计 268dp，在 320dp 屏上有 28dp 余量。为此去掉了 chip 上的箭头——四枚各 24dp、共 96dp，比整段余量还多，而 chip 自身的底色已经表明它可以点。
- **输入框外边框**：边框从 1dp 提到 1.5dp，解算目标从 3:1 提到 3.5:1，新增 `edgeOn(surface,ratio)` 重载。刚好卡在 3:1 的 1dp 细线是"能过"而不是"看得清"，而输入框是用户触碰最多的控件。
- **会话行距**：会话行此前上下各 10dp，标题、元信息、日期与分隔线压在大约 66dp 内，两条会话看着像一块。上下内边距各增至 15dp（1.5 倍），标题与元信息之间加 3dp。
- **任务完成后折叠全部执行过程**：`observeCompletion` 原来只清空 `expanded`，但活动行在**不在 `collapsed` 里**时也会自展开——清空开放集合等于把决定权交还给默认值，刚跑完的过程过一会儿又自己展开了。现在两个集合都写：清空开放集合，并把该页所有活动行显式加入折叠集合，只留下总结。

**输入框上方的改动条**

- **点击向上展开**：详情面板现在排在横条之前，从横条上方展开、向转录区里长，而不是把输入区往下推。
- **折叠图标在左**：箭头成为横条里的独立视图而不是文字的前置 drawable，文字占据其余全部宽度，因此可以真正居中——围绕文字量出的 drawable 永远做不到这一点。
- **改动统计居中**：横条是「箭头／统计／等宽占位」三段，右侧占位与左侧箭头同宽，居中的是横条本身，而不是两个不等宽邻居之间的中点。
- **高度适应字体**：横条高度由该行的字体度量算出（`descent − ascent` 加对称内边距），不再钉死在 44dp 的条带上；同时用 `TouchDelegate` 补足触摸高度。为防 `WRAP_CONTENT` 的列把定高横条撑开，横条被包进一层同高的容器再入列。

**上下文窗口环**

- **环看不清**：环画在 40dp 的发送按钮上，弧线只从边缘内缩 2dp、线宽 3dp，一半压在主色圆面上、一半压在外面，弧与圆的边缘糊成一片，整个控件看上去是一颗实心点加一个数字。现在圆面按环宽内缩，弧线正好落在按钮自己的底色上，环宽取半径的 16%。
- **弧线与轨道同色**：轨道是写死的白色低透明度，进度弧是 `onPrimary()`——在浅色主题下两者都是白色，对底色都是 6.25:1，完全重合，这正是「看不清」的第二层原因。四个颜色现在都由 `towardExtreme()` **解算**而不是挑选：从首选色出发，朝黑或白方向推进直到与底色拉开指定比值。方向不再用「底色亮度是否大于 0.5」判断——中绿底色的亮度在 0.3 上下，旧判据把每一个弧都推向白色，包括浅色主题下本该避开白色的那些。
- 新增七组色板断言（进度弧／警告／危险对主色 3.0:1 以上，轨道 1.2:1 以上）。修复前 `midnight` 上警告色只有 **1.37:1**、`dark` 上危险色只有 **1.95:1**，都低于可辨认下限。
- **对比度与差距仍然不够（本轮）**：上一轮解决了"同色"，但描边只有半径的 14%、轨道对比只解到 1.35:1，环在 40dp 的按钮上依旧是"知道有、看不出差多少"。本轮把描边提到半径的 **20%**（28px 半径上由 4px 到 5.6px），轨道对主色解到 **1.9:1**、进度弧解到 **7.0:1**、警告与危险各 **5.5:1**。真正拉开的是**进度弧与空轨道之间的差**——那是用户唯一要读的信息，此前两者都贴着主色，占用多少看着一样满。

**尺度系统**

此前界面看着不整齐，根因不是配色而是没有尺度：同一个语义在十几处各写各的字面量，改一处不影响其余。本轮把尺度全部收进 `NativeUi`，并加了一条校验把字面量挡在门外。

- **字号**：新增 `CAPTION 11 / LABEL 13 / BODY 15 / TITLE 17 / HEADING 24 / DISPLAY 34 / TOUCH 48` 七级语义字号。所有源文件不再出现裸 sp 字面量。
- **行高**：新增 `ROW 48 / ROW_TALL 56 / BAR 68`。此前 48/50/52/54/56/60 六种高度在 27 处并存，同一列表内的行高都不一致。
- **圆角**：新增 `CORNER_CHIP 10 / CORNER_ROW 14 / CORNER_CARD 18 / CORNER_SHEET 24`；`NativeUi.input()` 此前用的是裸 `14`，现改为 `CORNER_ROW`。
- **间距**：新增 `SPACE_TIGHT 4 / SPACE_INLINE 8 / SPACE_STACK 12 / SPACE_PAGE 16 / SPACE_GROUP 22`。
- **图标**：新增 `GLYPH_INLINE 18 / GLYPH_ACTION 22 / GLYPH_DISPLAY 40`，收编原先 12/16/18/19/20/22/23/24/38/54 共 11 种尺寸、约 30 处调用。
- **阴影**：新增 `LIFT_FLAT 0 / LIFT_HEADER 2 / LIFT_FLOATING 3 / LIFT_POPUP 5 / LIFT_DIALOG 10`，层级顺序原本就正确但从未命名。
- **字重**：新增 `emphasize() / strong() / monospace() / monospaceStrong()` 四个语义方法，取代 4 种写法各异的 `setTypeface`。此前「源代码管理」页标题是 BOLD，而会话页标题是 medium，同一级标题两种字重。
- **分隔线**：3 处绕过 `NativeUi.rule(surface)` 直接画线，其中悬浮导航栏顶边是全局最淡的一条；现已统一，并补上 `rule(parent, surface)` 重载。
- **其余**：`StatusOverlay` 曾把 `CAPTION` 当图标尺寸用；欢迎卡的两个按钮一个是 54dp 一个是 48dp。

**桌面宠物**

悬浮窗折叠态的形象此前是手绘矢量，本轮换成从参考素材提取的线条小狗。

- **提取**：参考图是一白一黄两只贴在一起的形象，两者共用一条黑描边。轮廓追踪在此失败，原因值得记下——共享描边把白毛切成互不连通的几块，边界追踪只能跟住其中一块，返回的轮廓横扫整个画面而不是绕着身体走。两只重叠也无法拆分，因此按其原始构图作为一个形态使用。
- **表示**：素材本身已是平涂且尺寸接近精灵，故直接存像素。不是 64×64 的 RGB，而是 6 色索引加一个透明索引，一字节一像素，经 zlib 压缩后 base64 共 667 字符——比矢量版更小，Android 侧只需 `Inflater` 与 `Bitmap`。取色为 `#ffffff` 白、`#e9cc9c` 金、`#2b2b2b` 描边、`#f5e2b9` 浅金、`#ccb296` 阴影、`#ffcbc6` 腮红。
- **解码**：只解一次并在实例间共享；解码失败时回退到同色系的简化轮廓，不会留下隐形的宠物。
- **裁剪居中**：初次编码把参考图四周的空白一并带入，形象落在精灵下三分之二，气泡里看着偏低。改为按内容边界裁切后重排，填充率提升 27%。
- **画布映射**：`draw()` 一直用固定 64×64 坐标，却从未映射到 bounds。设置页建的是 52dp，在该尺寸下会按原生比例绘制并被 `clipRect` 裁掉；现按 bounds 等比缩放居中。
- **名册**：由 6 种（加「简洁」共 7 项）减为 2 种（共 3 项）。删去猫、兔子、小鸟、软糖、幽灵与手绘金毛，只保留线条小狗与机器人，避免同一选择器里混入两种画风。`PetSprite.migrate()` 会把设备上残留的旧名字归一到有效形态——此前默认值仍是已删除的 `linepup`，老设备读到死值后设置页会显示与实际不符的名称。

**互动效果**

折叠态桌面宠物此前只有呼吸、眨眼、跳动与状态反应，触摸只能拖拽和开气泡，宠物本身对触摸没有反应。本轮补齐三条触摸路径，并把状态与环境反应扩到十种。

- **抚摸**：手指按下即闭眼、身体向手倾斜并持续冒心；按住不动时爱心持续上升扩散，按得越久给出越多。
- **连点**：每次点击冒出星星爆发，连击数越高星数越多、越大、颜色越亮。连点四次自动展开气泡，避免误触时气泡反复弹出。
- **长按**：超过 380 毫秒转为惊吓——弹出感叹号、身体后缩，气泡同时展开。
- **拖动**：拖动与抚摸互斥，移动超过 8dp 即撤下触摸反应，宠物不会在移动途中还扭动。
- **新消息**：红心从肩头弹出。
- **到场**：切换形态或悬浮窗首次出现时冒出两个音符。
- **闲置**：空闲时每隔数秒自发飘一颗小心。
- **执行中**：头顶四个标记绕行。
- **思考中**：三颗星星依次亮起。
- **打盹**：一个 z 字上升淡出。
- **跳动**：落地时三点火花扩散收缩。
- **回落节奏**：脉冲衰减最初只有 4 帧（约 0.2 秒），点击反应快到来不及看清，已放慢到约 0.55 秒。
- **动作幅度与种类（本轮）**：上一条补的是"有哪些反应"，用户反馈的是"看得见多少"。实测问题在幅度而不在数量——常态呼吸只有 2.8%、活跃 5.5% 的缩放，在 64dp 的宠物上不到两像素，静止时和一张贴纸没有区别。本轮把呼吸提到 6.2%／9.5%，跳跃高度由 11 提到 15，并给每个状态各配一组**持续动作**而不是一个静态姿态：执行中叠加双倍频摇摆与约 ±3.4° 的整身摇晃、思考中点头配三段式侧摆、等待中蹭步配最大侧摆。区别在于以前只有"状态切换的那一下"能动，现在是**任何一个状态停住时也在动**。

## 2.0.13 · Windows / Android · 2026-10-08

在 2.0.12 之上继续处理会话目录、重启、排队消息、同步与预览速度以及整体视觉；源码、构建脚本与文档中的版本号已同步到 2.0.13，Windows 与 Android 安装包已在 `dist/` 生成。

- **会话目录**：Claude 的会话「工作目录」与「项目目录」此前被混为一谈，手机优先取了来源目录，于是浏览和预览都在另一棵目录树上，文件读取又会回退到重建整段会话记录。现在以会话自己的工作目录为准、项目目录作为回退，并在会话信息中同时列出两者；会话列表与项目筛选只按项目目录分组。新建会话仍会核对实际目录，不一致时明确提示。
- **重启客户端**：关闭后立即重新激活会被 Windows 忽略，因此重启看起来失效而启动、关闭正常。现在关闭后等待稳定再启动、激活最多重试三次，普通程序启动失败也会重试一次。
- **排队消息**：写入前的门闩只靠「会话签名变化」释放，而 Claude 的会话行没有轮次标识、活动时间也未必变化，导致门闩再不打开、队列里的消息永远发不出去。现在改为「已派发且超过宽限时间即放行」，没有轮次标识的后端也能排空。
- **同步与进入速度**：空闲且未变化的会话直接回答「未变化」，不再重建整段记录；助手对同一会话的详情做两秒短期缓存，写操作会使其失效；手机只在内容版本变化时才写会话缓存。会话页轮询在有输出时约一秒、空闲约两秒。
- **预览速度**：目录与文件读取不再重建会话详情；大体积文本预览不再回传第二份 base64 副本（仍可按需索取），小文件保持不变。
- **悬浮窗**：正文变化时整圈边框的彩色带环绕流动，气泡本身同时上抬并轻微放大；审批与提问仍是独立的脉冲提醒。
- **改动统计**：输入框上方的改动统计此前在只有文件改动、没有步骤时展开后只有 48dp 高，看不出任何内容，也不列出文件名。现在按内容计算高度、列出改动文件名、加减色跟随主题，并在展开时淡入。
- **上下文圆环**：发送按钮外圈的占用弧此前用的是与按钮填充相同的绿色，不到 75% 时看不出来；现在轨道与进度弧都改为与填充对比的前景色，75% 转琥珀、90% 转红。
- **输入与对比度**：Git 提交框、提问表单、重命名框改用与消息输入框一致的可见边界；按钮禁用态文字改用主题次级色，深色主题下不再发白难辨。
- **界面细节**：会话输入框改为有可见边界与投影的输入面，并与上方内容分隔；会话列表每行都显示所属项目；设置项改为分组卡片；弹窗统一为带抓手、标题栏与一致内边距的卡片；折叠项统一为带方向指示与底色变化的按钮；画布上的硬编码浅色改为主题色。
- **启动速度**：助手窗口先显示，网络、队列、托盘与客户端集成在其后启动。

构建说明：本轮按要求仅打包，未运行测试或 Windows 自检，未上传 GitHub；Android 构建脚本自带的签名与对齐校验正常完成。安装包校验值见 `dist/SHA256SUMS.txt`。
