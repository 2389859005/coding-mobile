# 桌面端与安卓端 UI 重设计方案

日期：2026-11-08。基于 2.2.2 的现有界面（`.local/ui-captures` 中的模拟器截图与当前代码）、两个参考项目，以及配套原型 [ui-redesign-prototype.html](ui-redesign-prototype.html)。本方案只改界面与交互组织，不改连接、配对、队列和会话数据流。

## 1. 依据

**本项目现状。** 手机端是纯代码构建的原生 View（`NativeUi.java` 提供颜色与控件，`MainActivity.java` 组装页面，`SettingsScreen.java` 负责设置）；桌面端是 customtkinter（`appearance.py` 生成色板，`desktop.py` 负责窗口与概览，`desktop_workbench.py` 负责工作台、通知、账号与日志）。2.2.2 已经统一了浅色、深色与跟随系统，设置页也按用途分组，这部分方向是对的，问题集中在层级和信息密度上。

**codex-mobile-bridge。** 值得借的是桌面工作台的结构：左侧会话列表，中间对话常驻，右侧文件预览作为并列面板打开，而不是替换对话；输入区上方一排“模型 · 推理强度 · 权限”的值胶囊；审批卡用暖色底把“允许运行此命令？”和命令本身放在一起。它的弱点是桌面概览页大片留白、按钮层级不清，这里不照搬。

**dsh-Go。** 借的是规则而不是外观：五种页面骨架（枢纽、详情、列表、表单、弹层）；“一屏只有一个主色实心元素”；卡片内不画分隔线、靠行高和间距分组；4 的倍数间距、卡片 20 / 弹层 28 的圆角；状态色只表示状态；空状态、加载和出错都要有设计过的样子。没有复制 Flutter 代码、品牌、吉祥物或配色预设。

## 2. 现状问题

以下问题来自 2.2.2 截图和代码，按影响排序。

手机会话页里，最需要用户处理的东西没有最高的视觉权重。审批卡被塞进“执行详情”折叠面板，和步骤列表共用一张卡，用户要先展开才看到“本次允许 / 拒绝”。与此同时，发送键是一个 56dp 的深色实心圆，中间写着“10%”，它比审批按钮更抢眼。

顶栏承载了太多零散信息：标题、状态点、“已同步”、文件夹图标、“0 轮对话”、信息按钮挤在一行，“0 轮对话”这种低频信息却占了固定位置。输入区的“模型 / 思考 / 审批 / 插件”四个小方框只写类别不写当前值，用户必须点开才知道现在用的是哪个模型。

会话列表的筛选区由三种不同控件拼成（灰底“全部项目”、下拉箭头、蓝字“按项目”），标题行又重复显示“DeepSeek 已连接”。会话行只有标题，没有项目、时间和运行状态，“归档”看起来像一个普通会话。

桌面工作台把对话、文件、Git、终端、智能体、侧聊做成同一区域的六个页签，切到 Git 时对话消失。底部一排“发送、停止、重试、归档、重命名、置顶”六个等宽按钮，破坏性操作和日常操作同权。会话列表用 ttk Treeview，行高 34、没有状态和时间。概览页只有居中的二维码，右侧和下方是空的，连接状态只在侧栏底部用一行小字表示。

颜色上，`StatusOverlay`、`ContextRing`、`FlowBorderDrawable` 仍有绕过主题的硬编码颜色（见 `packaging/android/native/UI_AUDIT.md` 的 S1–S3），桌面端与手机端的色值也各自推导，两端看起来不像同一个产品。

## 3. 设计方向

一句话：**界面退后，状态说话。** 这是一个“遥控器”，用户打开它通常只为三件事：看任务跑到哪了、处理一个审批或提问、再补一句话。所以界面的主角是“任务状态”和“需要你处理的事”，其余都安静。

整个方案只在一处用力：**状态脊**。每个会话、每轮执行在左侧都有一条 3px 的竖线，颜色只有四种含义：执行中（青，缓慢流动）、需要你处理（琥珀）、出错（红）、已结束（与分隔线同色，几乎看不见）。它在手机列表、手机会话、桌面列表、桌面对话和悬浮窗气泡里都是同一个符号，用户扫一眼左边缘就知道哪里需要自己。除此之外不加装饰性的渐变、光晕或彩色图标底；三家应用自己的图标是界面里唯一的“品牌色”。

### 3.1 颜色

两端共用一份色值表，手机写进 `NativeUi.theme()`，桌面写进 `appearance.py`，不再由色相公式各自推导。

| 角色 | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| 底 canvas | `#F4F5F7` | `#15181D` | 页面背景 |
| 面 surface | `#FFFFFF` | `#1E2228` | 卡片、输入区、列表 |
| 凹 sunken | `#ECEEF1` | `#262B32` | 代码块、值胶囊、按下态 |
| 线 line | `#E1E4E9` | `#2E333B` | 分隔、描边、已结束的状态脊 |
| 墨 ink | `#1B2230` | `#E6E8EC` | 正文与标题 |
| 次墨 muted | `#5F6876` | `#9AA3AF` | 辅助文字、图标 |
| 主色 accent | `#3A4C9C` | `#9DB0F0` | 主按钮、选中态、链接；一屏至多一个实心 |
| 主色浅底 | `#E8EBF6` | `#2A3250` | 选中行、用户消息气泡 |
| 执行中 run | `#10776A` | `#4FC2B0` | 状态脊、运行中标签 |
| 需要你 wait | `#9A6210` / 底 `#FBF3E4` | `#E2A64B` / 底 `#33291A` | 审批、提问、结果不确定 |
| 出错 error | `#B03F3A` | `#EE8F86` | 失败、断线、删除确认 |

主色沿用现有“雾蓝”色相，只是压深一档，老用户不会觉得换了产品。所有文字与底色组合都已计算对比度：正文 14.5:1，次墨 5.2:1 以上，主按钮白字 7.8:1，琥珀字在浅琥珀底上 4.6:1，均满足 WCAG AA。

桌面端现有的六种强调色（雾蓝、黛青、暮紫、松石、琥珀、石墨）建议收为“跟随默认”一种，与手机一致；如果要保留，只允许改主色和主色浅底两项，状态色不随强调色变化，否则“琥珀强调色”会和“需要你处理”撞色。

### 3.2 字体与字号

不引入新字体，两端都用系统中文字体（手机为系统默认，桌面为 Microsoft YaHei UI），代码与命令用等宽字体（手机 `monospace`，桌面 Cascadia Mono，缺失时回落 Consolas）。层级靠字重和颜色，不靠堆字号。

| 档位 | 手机 sp | 桌面 px | 字重 | 用途 |
| --- | --- | --- | --- | --- |
| 页面标题 | 22 | 20 | 600 | 列表页、设置首页的大标题 |
| 栏标题 | 17 | 15 | 600 | 顶栏会话名、卡片标题 |
| 正文 | 16 | 14 | 400 | 消息正文，行高 1.6 |
| 行文字 | 15 | 13 | 400/500 | 列表行、设置行 |
| 辅助 | 13 | 12 | 400 | 时间、项目名、说明 |
| 标签 | 12 | 11 | 500 | 状态标签、值胶囊 |

数字（时间、token、行数、+/- 统计）使用等宽数字。分组标题用 13sp 次墨常规字重，不用全大写或加粗。

### 3.3 间距、圆角与图标

间距一律取 4 的倍数：页面左右 16，分组之间 24，卡片内边距 16，列表单行 52、两行 64。圆角按层级区分而不是统一：小标签 6，值胶囊与按钮全圆，卡片 14，底部弹层 24，桌面窗口内的面板 12。卡片之间靠留白分组，卡片内的行不画分隔线（设置页除外，保留缩进的细线，便于长列表扫读）。

图标统一为 1.5 描边的线性图标，20dp/px；选中态用同骨架实心。去掉设置行的彩色圆底，只保留次墨色线性图标。

### 3.4 动效

只给“用户操作的回应”和“状态变化”做动效，时长 150–250ms，系统关闭动画或设置里“减少动态效果”开启时全部为 0。执行中的状态脊是唯一的持续动画：一段亮色沿竖线缓慢下移，周期 1.6s；减少动态时改为静止的实色。不做入场错位动画、弹跳或闪光。

## 4. 安卓端

### 4.1 会话列表（列表页骨架）

```
┌──────────────────────────────┐
│ Codex ▾            [电脑●] ⚙ │  标题即应用切换；电脑芯片显示连接
│ ┌ 搜索会话或项目 ─────── ⚲ ┐ │  搜索框整宽，右侧筛选按钮
│ 需要你处理                     │  有待处理时才出现的分组
│ ┃ 整理项目交接文档    待审批   │  琥珀状态脊 + 标签
│ 产品开发              按项目 ▾ │  分组头：项目名 + 排序菜单
│ ┃ 检查登录流程异常   执行中 3/5 │  青色流动脊
│ │ 补充 API 文档         10/02 │
│ 归档 4                        │  末尾一行文字入口
├──────────────────────────────┤
│   Claude    Codex    DeepSeek │  底栏三图标，待处理时图标右上小点
└──────────────────────────────┘
```

标题行只留“应用名 ▾”、电脑连接芯片和设置。电脑芯片是一个小胶囊：绿点加电脑名表示已连接，琥珀点表示重连中，点开就是现在的连接详情；“DeepSeek 已连接”这样的重复文字去掉。筛选从三个控件合并为搜索框右侧一个筛选按钮，打开底部弹层选择“按项目 / 按时间”和“显示归档”。

会话行两行：第一行标题和右侧时间或状态标签，第二行项目目录名。状态由左侧状态脊和右侧标签共同表达，标签只在执行中、待审批、待回答、出错时出现，已结束的会话只显示时间。所有应用里出现待处理事项时，在列表顶部出现“需要你处理”分组，这是首页唯一允许使用琥珀色块的地方。底栏三个应用图标保留，某个应用有待处理时在图标右上角显示 6dp 琥珀圆点（不显示数字，与宠物去角标的决定一致）。

### 4.2 会话页（详情页骨架）

```
┌──────────────────────────────┐
│ ‹  检查登录流程异常   ⌂  ⋯  │  标题一行；副标题：项目名 · 已同步
│    产品开发 · 已同步          │
│  ┌──────────────┐            │
│  │ 用户消息气泡    │ (主色浅底) │
│ ┃ ◉ Codex                     │  回复左侧状态脊
│ ┃ 正文 Markdown …              │
│ ┃ ▸ 执行过程 12 步 · 3 个文件 +48 −12 │ 折叠行，原位展开
│ ┌ 需要你确认 ───────────────┐ │  琥珀卡：常驻输入区上方
│ │ 允许运行此命令？              │ │
│ │ npm run test:auth           │ │
│ │ [ 拒绝 ]   [ 允许本次 ]      │ │
│ └───────────────────────────┘ │
│ ┌ 继续说点什么…               ┐ │
│ │ ＋ gpt-5.1·高  默认权限   ◎↑ │ │  值胶囊；发送键带上下文环
│ └───────────────────────────┘ │
└──────────────────────────────┘
```

顶栏左返回，中间标题单行省略，副标题一行写项目名和同步状态；右侧只留“工作台”和“更多”两个按钮。“0 轮对话”、会话 ID、工作目录、归档、重命名都进“更多”打开的会话信息弹层。标题本身也可点击打开同一个弹层。

待处理事项（审批、提问、结果不确定的提交）从“执行详情”面板里拿出来，做成输入区上方的独立琥珀卡。一次只显示最早的一件，多件时卡片标题写“需要你确认 1/3”，左右滑动切换。主按钮“允许本次”用主色实心，“拒绝”用描边，两者等高等宽；更多权限选项（总是允许、本会话允许）放在卡片右上角的“更多选项”里，避免误触。处理后卡片原位收起，并在回复流里留下一行记录“已允许运行 npm run test:auth”。

“执行详情”不再是输入区上方的面板，改为每条回复下的折叠行：“执行过程 12 步 · 3 个文件 +48 −12”，点击原位展开，内容沿用现在的步骤、文件变化和 diff。任务运行时，最后一条回复的折叠行改为“正在执行 第 3 步：运行测试”，左侧状态脊流动。

输入区是一张卡片：上方是多行输入，下方左侧“＋”附件，中间是值胶囊（写当前值，如“gpt-5.1 · 高”“默认权限”“2 个插件”），右侧是发送键。发送键缩小到 44dp，主色实心，外圈 2dp 的上下文环保留现有 75% 琥珀、90% 红的规则，但百分比不写在按钮里，改为长按显示。执行中且输入为空时发送键变为“停止”（方形图标，次墨底），有输入时变为“加入队列”，队列条数以小胶囊显示在输入框上沿。

新消息、回到顶部按钮、右侧快速滑块、撤回编辑、草稿与阅读位置保持等现有行为全部保留，只调整颜色和尺寸。

### 4.3 Git 与工作台

Git 页保持“右滑进入、上半更改、下半提交图”的结构，统一为详情页骨架：顶栏写仓库名和当前分支，分支名可点切换。暂存区与未暂存区作为两个分组，文件行左侧用 `M / A / D` 单字母等宽标识，颜色只用于 `+/-` 数字。提交输入框和“提交”主按钮固定在底部，获取、拉取、推送收进顶栏的同步按钮菜单，避免一排按钮同权。

工作台（文件、Git、终端、智能体、侧聊、通知）改为底部弹层，打开时默认半高，可拖到全高；顶部是可横向滚动的胶囊页签。这样从会话进入工作台时，对话仍在弹层后面，关掉就回到原阅读位置。

### 4.4 设置（枢纽页骨架）

现有分组（连接、外观与交互、通知与宠物、电脑）和搜索保留。在搜索框下加一张概览卡：左侧电脑图标，右侧“已连接 MMM-PC”和“临时 HTTPS · 延迟 86 ms”两行，点卡片进入连接详情；这取代分组里的“已连接电脑”行。设置行去掉彩色圆底，行尾显示当前值。开关行的说明文字只在需要时出现一行，长说明进详情页。

### 4.5 弹层、对话框与悬浮窗

所有选择类弹层（模型、思考强度、审批模式、插件、归档、会话信息）统一为底部弹层：拖把手、左标题右关闭、内容、至多一个主按钮，圆角 24。确认类（删除、归档、放弃编辑）用居中对话框，危险操作按钮用红色文字而不是红色实心。

悬浮窗宠物与气泡的颜色改为直接调用 `NativeUi.theme()` 的结果（UI_AUDIT S1 的改法），气泡左侧同样有状态脊，和主界面一致。

## 5. 桌面端

### 5.1 窗口结构

```
┌──────┬──────────────────────────────────────────────────────┐
│ ◧    │                                                      │
│ 概览  │                 当前页面                              │
│ 工作台 │                                                      │
│ 通知 3│                                                      │
│ 账号  │                                                      │
│ 日志  │                                                      │
│      │                                                      │
│ ⚙设置 │                                                      │
│ ● 手机已连接                                                  │
└──────┴──────────────────────────────────────────────────────┘
```

侧栏从带边框的圆角卡片改为贴边的导航栏（宽 184，窄于 1000px 时收为 56 的图标栏），背景用“底”色，与内容区靠色差区分，不画描边。导航项：概览、工作台、通知中心（带未读数）、账号与模型、日志；“应用设置”放到侧栏底部与其他项分开。侧栏最底部常驻连接状态：圆点加“手机已连接 · 临时 HTTPS”，点击回到概览。

### 5.2 概览

概览从“只有一个二维码”改为两栏。左栏是配对卡：顶部“临时扫码 / Tailscale 永久”分段控件，下面二维码、有效期倒计时和“刷新二维码”；已经配对时二维码收起，卡片改为显示已配对手机和“配对另一台手机”。右栏是状态列表，每行一个状态点：网关（运行中、端口 8787）、公网入口（临时 HTTPS 已就绪）、Claude、Codex、DeepSeek 三个客户端是否在运行（不在运行时行尾给“启动”按钮），以及“最近活动”里最后三条通知。空白区域因此承载了用户最常问的问题：现在能不能用？

### 5.3 工作台（三栏）

```
┌───────────────┬───────────────────────────────┬─────────────────┐
│ 全部 Claude Codex DS │ 检查登录流程异常   执行中  ⋯ │ 文件 Git 终端 … │
│ ⚲ 搜索            │                               │                 │
│ 需要你处理         │   消息流（阅读列最宽 720）       │  右侧检查器        │
│ ┃ 交接文档 待审批   │                               │  按页签显示文件树、 │
│ 产品开发           │  ┌ 需要你确认 ─────────────┐ │  Git 更改、终端、   │
│ ┃ 登录流程  3/5    │  │ npm run test:auth      │ │  智能体、侧聊      │
│ │ API 文档  10/02  │  └─────────────────────────┘ │                 │
│                   │  ┌ 输入 ───────────────────┐ │  底部：上下文环、   │
│ ＋ 新建会话         │  │ ＋ 模型 思考 权限    ◎↑ │ │  队列             │
└───────────────┴───────────────────────────────┴─────────────────┘
```

核心改动是对话常驻中间，文件、Git、终端、智能体、侧聊移到右侧检查器，以页签切换，对话不再被替换。窗口宽度小于 1100px 时检查器折叠为右侧一条 40px 的图标栏，点击以覆盖层展开。

左栏会话列表用自绘行替换 ttk Treeview：每行左侧状态脊，标题加时间或状态标签，第二行项目名；顶部是“全部 / Claude / Codex / DeepSeek”分段控件和搜索框；“新建会话”放在左栏底部。

中栏顶部标题栏：会话名、状态标签、右侧“⋯”菜单（重命名、置顶、归档、复制会话 ID、在桌面客户端打开）。消息流用 `CTkTextbox` 的 tag 实现：用户消息右对齐浅底，回复左侧留 12px 并画状态脊，代码块用凹色底和等宽字体。待处理卡与手机一致，放在输入区上方。输入区底部左侧是值胶囊（`CTkOptionMenu` 换成扁平样式），右侧发送键；停止与加入队列的逻辑与手机一致，“重试”只在提交结果不确定时以横幅按钮出现。现在的六个等宽操作按钮全部移除。

Git 检查器：分支选择、暂存与未暂存两个列表、提交说明输入框和“提交”主按钮；获取、拉取、推送放在分支行右侧的同步菜单里。终端检查器保留“本机 / WSL / SSH”选择和“只有点击运行才执行”的规则，输出用深色等宽卡片（浅色模式下也保持深底，便于区分命令输出与对话）。

### 5.4 通知、账号与模型、日志、设置

通知中心按“需要你处理 / 已完成 / 系统”三组排列，每行状态脊加会话名、时间和“打开会话”。账号与模型按客户端分三张卡，每张卡显示登录状态、当前模型和用量。日志页保留搜索与“跟随”，日志区用等宽字体、深色底，级别用状态色的小标签。应用设置按“连接、外观、通知、电脑”分组，与手机设置同名同序。

### 5.5 customtkinter 的实现边界

customtkinter 不支持阴影、逐角圆角和真正的富文本，以下做法保证方案可落地：卡片只用底色差和 1px 描边，不做阴影；状态脊用 3px 宽的 `CTkFrame` 放在行或消息左侧，执行中的流动效果用 `after()` 每 120ms 改一次颜色（三档亮度循环），减少动态时不启动定时器；会话列表行用 `CTkScrollableFrame` 中的自绘行，超过 200 行时只渲染可见区域附近的行；消息流继续用 `CTkTextbox`，通过 `tag_config` 实现缩进、底色和等宽字体，图片和 diff 预览保持现在的打开方式。

## 6. 实施顺序与改动范围

建议分三步发布，每一步都可以单独回退。

第一步是颜色与基础控件，两端都不改布局：用第 3.1 节的色值替换 `NativeUi.theme()` 与 `appearance.palette()`；修复 UI_AUDIT 的 S1–S3（悬浮窗、上下文环和流光边框改为取主题色）；新增 `RUN`、`WAIT`、`WAIT_BG` 三个颜色；设置行去掉彩色圆底。改动集中在 `NativeUi.java`、`StatusOverlay.java`、`ContextRing.java`、`FlowBorderDrawable.java`、`SettingsScreen.java` 和 `appearance.py`。

第二步是手机端结构：会话列表的标题行、筛选弹层、两行会话行与“需要你处理”分组；会话页顶栏精简、待处理卡独立、执行过程改为回复下的折叠行、输入区值胶囊与 44dp 发送键；设置概览卡。主要改 `MainActivity.java`（列表与会话页组装）、`SessionPage.java`、`MessageContent.java`、`FloatingNavigation.java`、`ContextRing.java`、`SettingsScreen.java`，并新增 `StatusSpine.java`（状态脊 Drawable，含流动动画与减少动态分支）和 `PendingCard.java`。

第三步是桌面端结构：侧栏改导航栏、概览两栏、工作台三栏与检查器、会话列表自绘行、消息 tag 样式、移除底部六按钮。主要改 `desktop.py`、`desktop_workbench.py`，建议把检查器拆到新文件 `desktop_inspector.py`，把会话行拆到 `desktop_rows.py`，避免 `desktop_workbench.py` 继续膨胀。

现有的 `test_native_ui.py` 中依赖控件文字的用例（例如“执行详情”“0 轮对话”）需要随第二步更新；`ScanSettingsRegression` 与 `StatusLayoutRegression` 要按新结构补断言：待处理卡在输入区上方可见、执行中的会话行有状态脊、会话页底栏隐藏。

## 7. 验收标准

视觉上，一屏内至多一个主色实心元素；所有文字对比度达到 WCAG AA；浅色、深色和跟随系统三种模式下，状态脊的四种颜色都能分辨。手机端在 360dp 宽、系统字号 1.3 时，会话列表行、待处理卡按钮和输入区值胶囊不折成竖排、不溢出；桌面端在 800×650 最小窗口下侧栏收为图标栏、检查器折叠，对话仍可完整阅读与输入。

交互上，待审批或待回答时不需要任何展开操作即可在会话页看到“允许本次 / 拒绝”或回答入口；停止、加入队列、撤回编辑、草稿与阅读位置保持的行为与 2.2.2 一致；开启“减少动态效果”后没有任何持续动画。

原型中的会话名、命令、数字均为示例数据，仅用于展示布局。
