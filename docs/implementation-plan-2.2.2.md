### 手机端修改方案

1. **页面结构**

   - 保留固定底部导航和持久化页面容器。
   - 切换会话、设置、项目时只更新内容区域，不销毁整个页面。
   - 会话列表、消息列表、设置页分别保留滚动位置、输入草稿和展开状态。
   - 使用局部差量更新，避免切换页面重新加载全部数据。

2. **实时连接**

   - 建立统一的实时连接管理器。
   - 优先使用 WebSocket/SSE，失败后自动降级为短轮询。
   - 增加心跳、断线重连、指数退避、网络切换监听和连接状态标识。
   - 会话列表、当前会话、任务状态、审批请求共用同一事件流。
   - 连接恢复后只拉取变更记录，不重新刷新整个页面。

3. **ChatGPT 会话同步**

   - 桌面端桥接层统一返回 Codex、Claude、DeepSeek、ChatGPT 会话。
   - 为会话增加稳定的 `source/backend/sessionId` 标识。
   - 移动端按来源显示会话，避免只识别前三种后端。
   - ChatGPT 新建会话、消息更新和完成状态进入同一实时事件流。

4. **会话页**

   - 输入框固定在底部，键盘弹出时自动调整可视区域。
   - 统计信息改为输入框上方的紧凑折叠条。
   - 展开后使用页面内覆盖层，不使用居中弹窗。
   - 统计内容按模块分组：上下文、连接、任务、队列。
   - 只显示必要数字，避免横向过长的大条形布局。
   - 执行记录、审批、待回答内容使用紧凑卡片和折叠区域。

5. **图标与视觉**

   - 所有 `</>`、文字箭头、伪图标替换为统一矢量图标。
   - 建立图标映射表，统一尺寸、颜色、无障碍描述。
   - 设置页改为紧凑分组卡片，减少大面积空白。
   - 会话页、设置页、连接页使用同一套间距、圆角和状态色。

### 桌面端修改方案

1. **工作区布局**

   - 左侧为会话与项目导航，中间为当前会话，右侧为上下文和任务状态。
   - 侧栏可折叠，窗口较窄时自动切换为抽屉。
   - 会话、任务、审批、连接诊断保持在当前工作区内，不频繁弹窗。

2. **实时同步**

   - 桌面端维护唯一实时事件总线。
   - 会话列表、当前会话、悬浮宠物和系统通知订阅同一事件源。
   - 新消息、任务完成、错误、审批请求即时推送到各个界面。
   - 页面切换只切换视图，不重建连接和会话缓存。

3. **会话体验**

   - 支持会话草稿、滚动位置、展开状态和当前筛选条件持久化。
   - 执行步骤默认折叠，错误和待处理事项自动展开。
   - 任务完成、失败、中断、等待输入使用不同颜色和图标。
   - 发送、停止、重试、审批、继续任务统一使用紧凑操作栏。

4. **连接与诊断**

   - 顶部显示连接状态、延迟、最近同步时间。
   - 增加连接质量分级：正常、延迟、重连中、离线。
   - 提供重连、刷新当前数据、查看最近错误的入口。
   - 多客户端连接时由桌面端统一分发状态，避免各页面重复请求。

5. **桌面宠物联动**

   - 桌面主界面、桌面宠物、系统通知使用相同的事件优先级。
   - 重要事件在桌面端和宠物上同时反馈。
   - 普通消息只更新状态，不产生高频打扰。
   - 宠物点击可直接定位到具体会话或审批项。

### 悬浮窗与宠物修改方案

1. **统一状态机**

   状态分为：

   - 空闲
   - 工作中
   - 思考中
   - 等待回答
   - 等待审批
   - 已完成
   - 出错
   - 断线
   - 静默

   事件按优先级处理：

   `错误/审批 > 待回答 > 完成 > 新消息 > 普通进度 > 空闲动画`

   避免多个状态同时触发导致动作冲突。

2. **动作设计**

   - 工作中：规律摆动、快速节奏。
   - 思考中：头部倾斜、星光提示。
   - 等待回答：轻微靠近屏幕外侧并显示提示标记。
   - 等待审批：琥珀色提醒、短暂弹跳。
   - 已完成：绿色庆祝动作和短暂粒子效果。
   - 出错：红色警示动作，保持数秒后回到普通状态。
   - 断线：变暗、暂停动作，并显示重连状态。
   - 空闲：呼吸、眨眼、偶尔轻微互动。
   - 长时间无任务：进入睡眠动作。

3. **显示模式**

   提供四种模式：

   - **完整动作**：显示宠物、状态徽标和气泡。
   - **仅重要事件**：普通空闲时隐藏，有审批、错误、完成时出现。
   - **仅状态角标**：保留小型状态徽标，不显示完整宠物。
   - **静默**：完全隐藏悬浮窗，但连接仍保持。

   另加：

   - App 前台是否继续显示。
   - 是否自动吸附屏幕边缘。
   - 气泡最大宽度和显示时长。
   - 动画速度和勿扰时段。

4. **交互设计**

   - 单击：展开跟随宠物的状态气泡。
   - 双击：直接打开当前活跃会话。
   - 长按：打开跟随宠物的操作菜单。
   - 拖拽：移动宠物，松手自动吸附左右边缘。
   - 点击任务卡片：进入对应会话。
   - 点击审批或待回答卡片：直接进入处理位置。
   - 点击气泡外区域：关闭气泡。
   - 长按菜单提供：打开应用、打开当前会话、隐藏一小时、切换显示模式、关闭悬浮窗。

   菜单改为悬浮窗内部的锚定菜单，不使用 `AlertDialog`。

5. **显示与性能**

   - 空闲时降低动画频率，重要事件时临时提高帧率。
   - 使用屏幕安全区域，避免遮挡刘海、导航栏和输入法。
   - 横竖屏变化时重新计算位置和气泡方向。
   - 断开连接时保留宠物本体，避免悬浮窗突然消失。
   - 权限撤销、服务重启、窗口被系统移除时自动恢复。
   - 低电量或后台限制时降低轮询和动画频率。

### 实施顺序

1. 先改实时连接和统一事件总线。
2. 再改手机端页面持久化和会话同步。
3. 再改桌面端工作区与连接诊断。
4. 最后改悬浮窗状态机、宠物动作和交互。
5. 完成 Android 回归测试、桌面端回归测试和连接中断测试。
6. 只更新源码和版本元数据到 **2.2.2**，本轮不打包。

验收标准是：页面切换不刷新会话、ChatGPT 会话能在手机端出现、实时状态延迟明显降低、宠物动作与事件一致、悬浮窗菜单不再使用弹窗、普通状态不产生频繁打扰。

**桌面端功能增量**

1. **线路健康与自动选择**
   每条线路记录连接延迟、握手时间、最近成功时间、失败次数和冷却状态；自动选择最快可用线路，失败后按候选线路切换。桌面端和手机端共用同一套连接状态模型。

2. **网关生命周期管理**
   启动、停止、重启显示明确影响范围；重启前提示正在执行的任务；服务启动、端口占用、客户端未连接等状态都在概览页直接呈现。

3. **客户端能力面板**
   显示 Claude、Codex/ChatGPT、DeepSeek 是否已安装、是否运行、是否可接入、支持哪些模型和操作，并提供“启动、重连、查看日志”快捷按钮。

4. **设备与通知中心**
   桌面端查看所有手机的在线状态和最后心跳；通知支持按客户端和会话去重，展示发送失败原因与重试状态。

5. **诊断工具**
   一键导出脱敏诊断包，包含线路探测、服务状态、版本、端口、客户端发现结果和最近错误摘要，不包含凭据和聊天正文。

6. **桌面工作台入口**
   增加“打开工作台”，直接进入统一会话、文件、Git、终端页面。桌面端和手机端共享会话状态、实时事件和草稿，不再维护两套状态逻辑。

当前 `Desktop` 类同时负责窗口、服务启动、路由、网络检测、托盘和设置。建议拆为：

---

建议采用“原生壳保留、状态层重构、工作台逐步升级”的路线。参考项目是 Android/iOS 原生壳加共享 Web 工作台；当前项目是纯原生 Java，直接迁移整套 Web UI 风险较高。当前 [MainActivity.java](D:/download/vscodetest/coding-mobile/packaging/android/native/MainActivity.java:574) 在切换页面时调用 `reset()`，会重建视图并断开实时连接，这是刷新会话的主要原因。

| 方向 | 当前问题 | 建议 |
|---|---|---|
| 页面切换 | `showTab()`、`openSession()` 重建页面 | 引入常驻 `AppState`、`NavigationHost`、页面缓存；切换只改变可见层，保留滚动位置、草稿、展开状态、打开文件 |
| 实时连接 | SSE 只服务当前列表或当前会话，生命周期切换会断开 | 建立统一 `ConnectionSupervisor`，按“电脑 + 凭据 + 客户端 + 会话”管理订阅；前台保持 SSE，后台使用通知游标和长轮询回退 |
| 稳定性 | EOF、网络切换、隧道失败后的重连不完整 | SSE 心跳、EOF 重连、指数退避、线路健康评分、旧接口回退；连接失败不删除凭据，恢复后自动续接 |
| 首屏速度 | 打开会话先等待请求 | 先绘制本地缓存，再异步拉取增量；实时流只发送 revision 变化，未变化不重绘 |
| 统计条 | 刷新时整体重建，容易错位 | 固定一行紧凑 Chips，例如“步骤 3 / 改动 2 / 队列 1”；展开后使用页面内 `FrameLayout` 覆盖层，限制高度，不使用 Dialog |
| 设置页 | 与会话页使用宽长状态条 | 改为分组卡片和紧凑设置行，状态用右侧小标签或图标表示 |
| 图标 | [NativeUi.java](D:/download/vscodetest/coding-mobile/packaging/android/native/NativeUi.java:575) 的 `code` 图标被大量复用 | 建立 `IconRegistry`：会话、文件、Git、终端、审批、通知、网络、统计、设置分别使用语义图标；`</>` 只保留给源码/代码块 |
| ChatGPT 会话 | 数据层虽已允许部分 ChatGPT 来源，列表和详情仍可能因字段差异被过滤 | 统一 `provider/source/originator/thread_source/owner/cwd`，列表和详情共用同一判定；只排除明确的子代理记录；增加 ChatGPT Desktop 新建会话回归测试。若用户指 ChatGPT 云端网页会话，则需单独增加账号连接器 |
| 消息工作台 | 文件、Git、队列已有，但页面状态分散 | 借鉴参考项目的持久化标签：聊天、文件、Git、终端、智能体、侧聊；每个标签保存草稿、滚动位置和加载状态 |
| 通知 | 有任务监控，但缺少统一收件箱体验 | 增加按电脑、客户端、会话去重的通知收件箱；点击通知直接进入准确会话，前台真正显示后再标记已读 |

推荐拆成四个阶段：

1. **P0：实时与状态基础**
   抽出 `ConnectionSupervisor`、`SessionRepository`、`NavigationState`，修复页面切换重置；统一 SSE/长轮询、心跳、重连和 revision 校验。

2. **P1：UI 重构**
   重做主页、会话列表、聊天头部、输入区和设置页；统计条改为紧凑折叠覆盖层；完成所有语义图标和无障碍描述。

3. **P2：会话与 ChatGPT 完整性**
